From ticket 15's bench (P1, P2, P3). On the bench, Ven was on a phone. The lesson page can be reached that way (Take over of the bot's desktop from a phone), but driving a desktop VM through a phone is very inconvenient. The bot asked questions in Grok Bot chat widgets and hand-built `POST /api/chat` requests to save the answers into the lesson, so `lh answer` still saw them. That path is undocumented, and once the bot graded a pick before it had the confidence. The learner's standing preference: never reveal right or wrong until the confidence is in.

**What to build (recommended design; reopen only if the code makes it unworkable):**
- [ ] A new `lh` command, e.g. `lh submit <lesson> --after <cursor>`, that saves a learner's answer exactly as the page does (same request shape to the existing page route, POST /api/chat, so the stored answer is identical to a page answer). It takes the pick(s) by index, confidence (the page's values: 0/30/50/70/90/100), optional thinking, "I don't know", and skip. For quiz and probe picks, confidence is required unless the answer is "I don't know"; a pick without it is refused before anything is sent. Read the page's answer and dismiss request shapes (tests/bot-run-answers.test.ts, tests/bot-run-page-input.test.ts, ticket 09/14 smoke scripts) and mirror them. No new server route unless the page route cannot be reused; say why if so.
- [ ] Ticket 20 found the bench's LaTeX corruption came from the bot building the answer request inside a double-quoted shell string (bash expanded `$n`, `$k` to nothing). `lh submit` takes picks by index and never needs the question text; the guide tells the bot to pass any JSON that contains `$` through `--file` or a single-quoted heredoc, never a double-quoted string.
- [ ] Retried `lh submit` is safe to run twice (no duplicate answer).
- [ ] Guide: a section for a learner who answers outside the page (phone, chat widgets): ask in your own channel, collect pick + confidence (+ thinking) together, never say right or wrong before the confidence is in, save it with `lh submit`, then read it back with `lh answer`. Say that picks are read and sent by index, not label. Note that the learner can still reach the lesson page from a phone through Take over, but it is slow; the out-of-page path is the convenient one. Ven's intended flow (2026-11-01): the bot screenshots the question card page (`/chat/<id>/card`, ticket 22) and sends it, the learner answers in a chat widget, the bot saves it with `lh submit`.
- [ ] Guide, from the Watcher's Grok Bot capability notes (2026-11-01): only the main Grok Bot chat agent can raise chat widgets, not its subagents or routine runs, so the Bot Teacher itself asks. Grok Bot chat does not treat a single `$` as math; when mirroring a question, teaching text or plan into chat, convert `$...$` to `\( ... \)` (display math `$$...$$` and fenced `mermaid` render as they are). The screenshot of the card shows math as the page renders it, so it needs no conversion.
- [ ] Guide, Method section: update the "no equivalent" list with the Grok Bot tools that stand in for LearnHarness tools, per the Watcher-marked mapping in .scratch/external-teacher/grok-bot-tool-map.md: web search/fetch and subagents for `research`; mermaid in chat or an HTML/SVG screenshot for `visual` (generated images are illustrations, not exact diagrams); poppler-utils for `pdf`; shell on the box for `find`, `ls`, `grep`, `read` (copy the learner's notes to the box first); `demo` is screenshots plus a widget on a phone, interactive only through desktop Take over; subagents cannot raise widgets. Keep it short.

Completed (every checklist box has code, guide text or a test; none is deferred):
- `lh submit <lesson> --after <cursor>` (`scripts/lh.mjs`) reads one JSON object from `--file` or stdin: `picks` (card numbers), `confidence`, `thinking`, `dontKnow`, `text`, `other`, or `{"skip":true}` alone. It reads the lesson with `lh show`'s route, checks the answer against the question open at `--after`, and saves it through the page's own routes, POST /api/chat for an answer and POST /api/chats/<id>/dismiss for a skip. No server route was added. The reply is `lh answer`'s reply after the save, plus `repeat` and `toolCallId`.
- The answer record comes from the dock's own code. The dock's QuestionData builder moved, unchanged, into `questionDataOf` in `src/core/answer-submit.ts` (new), and `components/question-dock.tsx` now calls it (a net 50-line deletion there; `src/core/index.ts` exports the file). `planSubmit` builds the dock's AnswerRequest and runs upstream `buildAnswer`, so grading, the option snapshot, the explanation and the commitment match the page.
- Card order: `questionDataOf` orders options with ticket 22's `displayedQuestionOptions`, the function the card and the dock use. lh.mjs is plain Node with no build step, so it loads `answer-submit.ts` through tsx's `tsImport` (tsx is a dev dependency `npm ci` installs). Without tsx, `lh submit` refuses with `usage` and an `npm ci` hint. Other commands still need nothing. A submit costs about 0.5 to 0.7 s more than `lh show` for the load.
- Refused before anything is sent: unknown fields, non-integer or null picks (`usage`); picks out of range or doubled, a quiz or probe pick without a confidence of 0/30/50/70/90/100, confidence or "I don't know" where the page has none, a single-select pick beside `other`, fields a typed-answer question does not take (`invalid`, with the card's numbered options). Also `unread_input`, `bad_after`, `no_open_question`, and `answered` (with the `saved` answer).
- Retries: the same submit again is `"repeat":true` and saves nothing, with the same `--after` or a later cursor, until the bot posts after the answer. After that, `no_open_question`. A page answer racing a submit leaves one answer: `repeat` if equal, `answered` if not.
